**你当前的首要任务是把知识点 v0.9.9 评审稿整理成一致、可实现、可验收的规格，再负责六个模型、权限、审核事务和 API 落地。** 题库导入、Elo 与推荐、RAG、Agent、教学分析仍是后续后端工作，但不应全部塞进知识点一期。

K02 的错误响应必须以**修订后的知识模块契约**为准：`error=错误码字符串`、`data={message,retryable,details}`、`request_id`。旧学习/Agent/导入契约也采用这一结构，但旧运行时代码尚未实现完整包络和真实错误状态码。知识草案版本头为 0.9.9，实际冻结后才能统一为 1.0.0。

K04 不应只验证同一申请两次审核，也要验证“已有 A→B、C→D，同时批准 B→C 与 D→A”的跨申请竞争。仅锁各自端点无法防住该案例。可以先评审采用单一知识图事务锁等最简单的正确方案，不必引入图数据库或新依赖。

K03/K05 的引用检查必须与新增引用使用同一锁协议。否则一个事务通过废弃检查的同时，另一个事务可能新增映射或依赖，导致正式数据指向 deprecated 点。
