# 批量账号导入与临时凭据交付

适用于 `POST /api/admin/user`（CSV 导入）和现有 `POST /api/admin/generate_user`（按范围生成）。仅超级管理员可使用；导出只能由创建该批次的超级管理员下载，其他超级管理员也不能读取。

## 导入约定

```json
{"users": [["20260001", "张同学", "一班"], ["20260002", "李同学", "二班"]]}
```

- 每行依次为学号、姓名、班级，学号最长 32 字符，整批空数据、缺列或重复学号均拒绝。
- 新账号学号、生成账号的前缀和后缀统一小写；重复校验与已有账号匹配遵循登录的大小写不敏感规则。历史单个混合大小写账号不重命名、不改密码；历史多个等价账号明确拒绝，需单独解决歧义后再导入。
- 新账号使用 `secrets.token_urlsafe(18)` 独立生成 24 字符、144 bit 随机初始密码。用户表只保存 Django 密码哈希；不返回明文 JSON、不写日志。本轮不增加首次登录强制改密。
- 已有账号只更新班级，姓名、语言、密码、权限保持不变；凭据表只包含新账号。
- 账号、资料、导出回执在同一 PostgreSQL 事务内创建。凭据文件必须成功写入后事务才能提交；校验、数据库或文件写入失败不会留下半批账号或班级修改。

有新账号时，响应 `data` 包括 `file_id`、`created_count`、`updated_count`、`operation`、`created_at`、`expires_at`。全部是已有账号时 `file_id` 为 `null`、`created_count` 为 0，不生成新密码。

## 下载与重试

- 下载：`GET /api/admin/generate_user?file_id=<file_id>`，响应为 XLSX，列名为 `Username`、`Password`。
- 恢复列表：`GET /api/admin/generate_user?list=1`，返回当前创建者最近 100 个仍在有效期内的导出元数据，不含明文密码。
- 文件在创建后 **24 小时**内可重复下载，下载不会消费或删除文件。因此客户端断线、响应丢失或浏览器未保存文件时，可直接再次下载。
- 同一管理员在有效期内重试相同导入内容（行顺序也相同）或相同生成参数，返回原回执和原凭据；不会创建额外账号或修改密码。服务端按创建者加锁，防止并发重试重复创建。
- 大小写变体按规范化后的内容匹配重试；两个批量入口还共用事务创建锁，避免不同管理员并发创建等价用户名。锁等待沿用公共实现的5秒上限；失败回滚后可重试。
- 管理前端导入后自动发起下载，并显示“新账号凭据下载”。刷新页面会重新载入当前管理员的有效导出。导入 POST 响应丢失时，刷新列表或重新导入相同 CSV 可找回。
- 下载返回 `Cache-Control: no-store, private`，不允许浏览器/代理缓存。界面保留重试按钮，不把发起浏览器保存操作描述为已确认保存。
- 有效期不会因重试延长。到期后服务端拒绝下载，重新导入只更新班级，不重置密码。管理员应在到期前确认已保存并完成交付；若一直未完成交付，需要通过已有管理员改密流程明确重设，不能从哈希恢复初始密码。

## 存储和清理

- 默认私有路径为 `backend/data/user_credentials/`，不位于 `public`、`upload` 或静态资源目录中。目录权限 `0700`，文件权限 `0600`，文件标识是 32 字节随机值的十六进制表示。
- XLSX 完全在内存中生成，禁止 XlsxWriter 在系统 `/tmp` 写入包含密码的 XML。文件使用独占创建并刷盘；读取检查归属、权限、普通文件类型，并拒绝符号链接。
- 数据库 `user_credential_export` 仅包含创建者、请求摘要、计数、随机标识和时间；不存储明文密码或凭据文件内容。
- 创建、列表和下载请求都会执行过期清理。空闲服务必须持续运行部署工作进程，每 60 秒调用 `python manage.py cleanup_user_credentials`，以删除到期记录、文件及进程中断或管理员删除后遗留超过 24 小时的孤立文件。文件访问在到期时立即拒绝，定时物理清理最多滞后一轮间隔。
- 也可手工执行上述命令；输出仅含删除记录数，不输出密码或凭据内容。操作系统管理员仍可读取私有目录，应保持数据目录访问控制，并将临时凭据目录排除在长期备份之外。
- 孤立文件清理同时确认不存在回执，不会仅因文件mtime早于回执到期时间就删除仍有效的凭据。
- 首次部署须运行 `python manage.py migrate`（新增 `account.0014_user_credential_export`）。前后端应一同发布；旧前端不会展示新的导入凭据下载入口。
- 部署以现有共享 `DATA_DIR` 为文件存储边界；多应用实例必须共享该私有目录及一致的服务 UID，才能跨实例恢复下载。

## 共享权限边界

`BasePermissionDecorator` 及四个权限子类改为 `check_permission(request)`，不再在共享装饰器实例保存当前请求。禁用状态检查也使用本次请求的局部变量。这样并发的普通管理员、超级管理员及已禁用账号不能互相借用身份；所有原有使用这些装饰器的接口同步获得这一修复。
